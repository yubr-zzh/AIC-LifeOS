# 记忆抽屉 —— 任务清单与验收标准

> 目标（来自演示需求）：
> 1. 讲完一段话 → 打开抽屉 → 能指着刚新增的那一条
> 2. 看到「42 条」「引用 12 次」，立刻理解"它在积累"
>
> 参考实现：Koder Design《AI memory drawer》（右滑抽屉骨架）、Shape of AI《Memory》
> （"Mark the moment of capture"）、Agentic UX Patterns《Memory Inspector》
> （导航入口 + 对话内联 chip）。
> 原则：**只照抄骨架与信息层级，不引入新色**，继续用现有 token。

---

## 前置结论（已调研确认）

| 事实 | 影响 |
|---|---|
| 后端已有 `/memory`、`/memory/profile`、`/memory/markdown`、`correctMemory()`、`retractMemory()`、`importMemoryMarkdown()`、候选审核接口 | **抽屉不需要新接口**，编辑/删除/导出/导入都能直接接 |
| 记忆条目**没有** `used_count` 字段 | 「引用 12 次」必须**加后端计数**，前端不能编 |
| 记忆检索入口在 `lifeos/memory/retriever.py`，注入 prompt 在 `lifeos/agent/chat/runtime.py` | 计数点应落在**真正送进模型的那一刻**，而不是"检索到就算" |

---

## 步骤

### Step 0 · 摸清条目结构与注入点（15 min）

**做什么**
- 打印 `/memory` 返回的真实 JSON，列出每条记忆的字段（`text` / `source` / `category` / `scope` / `created_at` / ...）
- 定位「记忆被注入 prompt」的准确代码位置（`chat/runtime.py` 里构造 `SessionQueryContext` 之后、组装消息之前）

**Goal（做到什么程度算完成）**
- 有一张字段表，明确抽屉每一列取哪个字段
- 明确一个**函数级**注入点，能在这一行插计数
- 结论写进本文件

---

### Step 1 · 后端：加「引用次数」（25 min）

**做什么**
- `lifeos/memory/schema.py`：允许条目携带 `used_count`（缺省 0），并写进归一化字段表
- 在 Step 0 定位的注入点：对**真正送进 prompt 的**条目 `used_count += 1`，随记忆存储落库
- `/memory` 输出原样带上该字段
- 老数据缺字段时按 0 处理，不做迁移脚本

**Goal**
- 重启 exe 后连问两轮：第二条回答用到的记忆，「引用次数」变成 2
- 单元测试：命中一次计数 +1，未命中不变

> ⚠️ 这一步是「引用 12 次」的唯一来源。做不到就**不要显示这个数字**——
> 演示里出现假数据比没有这个数字糟糕得多。退化方案：显示「创建于 10-21 · 最近命中 10-27」。

---

### Step 2 · 前端：抽屉数据适配（10 min）

**做什么**
- 确认 `getMemory()` 的返回结构能直接喂给抽屉；需要则写一个 `toMemoryItems()` 适配层
- 决定分类分组维度：优先用条目的 `category`（偏好 / 项目 / 结论 / 反馈），缺失时回退到 `scope`

**Goal**
- 抽屉拿到的是统一形状的数组：`{ id, text, source, category, scope, createdAt, usedCount }`
- 有一条真实的测试数据能渲染出「42 条」这种量级（不足就灌种子数据）

---

### Step 3 · 前端：`MemoryDrawer` 组件（30 min）

**照抄 Koder 的骨架**

```
┌─────────────────────────────────────────┐
│ 记忆                            42 条 [✕] │
│ [🔍 搜索]                                │
├─────────────────────────────────────────┤
│ [全部] [偏好] [项目] [结论] [反馈]        │
├─────────────────────────────────────────┤
│ ▼ 偏好 (12)                              │
│   • 界面用绿色主题                        │
│     你写的 · 10-25 · 引用 4 次             │
│     [编辑] [删除]                         │
│   ─────────────────────────────          │
│   • 回答要短，别客套                      │
│     AI 提炼 · 10-21 · 引用 12 次          │
├─────────────────────────────────────────┤
│ [导出 markdown] [导入] [全部删除]         │
└─────────────────────────────────────────┘
```

**做什么**
- 右侧滑入浮层 + 半透明遮罩，`Esc` / 点遮罩关闭
- 顶部：标题 + **总条数**
- 搜索框：按内容实时过滤
- 分类 chips：切换分组，计数随分组变化
- 列表项：内容（2 行截断）、来源徽标（你写的 / AI 提炼）、日期、**引用次数**
- 行内「编辑」「删除」（删除二次确认）
- 底部：导出 markdown / 导入 / 全部删除

**Goal**
- 打开抽屉 → 立刻能看到总数、分类计数、每条的引用次数
- 搜索框输入即过滤，100 条以内不卡
- 编辑后列表即时刷新；删除后总数和分类计数同步减

---

### Step 4 · 入口与联动（15 min）

**做什么**
- 对话页顶栏加 `记忆 42` 按钮（数字 = 总条数）
- 打开抽屉时拉数据；关闭时不清缓存
- **联动**：点「从这段对话提炼记忆」→ 审核通过后，记忆总数自动 +1（轮询或事件）
- 刚写入的那一条在抽屉里标「刚刚」并高亮 5 秒

**Goal**
- 完整跑通：讲一段话 → 提炼 → 审核 → 打开抽屉 → **能一眼找到刚新增的那条**
- 顶栏数字同步变化

---

### Step 5 · 视觉打磨（15 min）

- 全部走现有 token，不引入新颜色
- 抽屉宽度 380–420px；条目之间用 hairline 而不是卡片套卡片
- 引用次数用弱化的等宽字，不抢内容
- 「刚刚」标记用主色小圆点 + 文案

**Goal**
- 镜头扫过去，观众第一眼落在「42 条」和「引用 12 次」上
- 与现有界面同一套视觉语言（浅底、白卡、细线、12px 圆角）

---

### Step 6 · 打包与演练（15 min）

- 替换 `Final_Software\dist\LifeOS\_internal\frontend\dist`
- 重启 exe，手动走一遍下面的演示脚本

**Goal**
- 双击 `Final_Software\dist\LifeOS\LifeOS.exe` 就能完整演，不需要 dev server

## 风险与退路

| 风险 | 退路 |
|---|---|
| Step 1 的注入点定位不到，计数做不了 | 隐藏「引用 N 次」，改显示「创建于 / 最近命中」 |
| 现有记忆条数太少（不到 10 条），看不出"在积累" | 灌一批种子数据（项目约定、偏好、结论），并在演示前先写几条 |
| 编辑/删除接口与抽屉字段对不上 | 先做只读抽屉，编辑/删除放二期 |
| `/memory` 返回的是原始 store 而非列表 | Step 2 写适配层，不动后端 |

## 验收清单

- [ ] 抽屉能打开，总条数正确
- [ ] 每条记忆显示来源、日期、引用次数
- [ ] 搜索可用，分类切换可用
- [ ] 编辑 / 删除可用，数字同步
- [ ] 提炼并审核一条记忆后，抽屉里能看到它且标着「刚刚」
- [ ] 顶栏「记忆 N」与抽屉内总数一致
- [ ] 全部走现有 token，无新增硬编码色值
- [ ] 打包后双击 exe 能完整演示
